# 게시판별 상세 기능 명세 (초안 v1)

작성일: 2026-08-19
목적: [new-site-ia.md](new-site-ia.md)에서 확정된 메뉴/권한을 화면·데이터·플로우 단위로 구체화. 기존 사이트 분석은 [xeadmin-site-analysis.md](xeadmin-site-analysis.md) 참고.

각 항목은 "데이터 모델 → 사용자 흐름(역할별) → Rhymix 구현 메모 → 열린 질문" 순으로 정리함. Rhymix 구현 메모는 실제 코드 조사 전 가설이며, 개발 환경 구축 후 검증 필요.

## 1. 캘린더 (About > 일정)

**목적**: admin이 확정된 행사 일정을 등록하면 전 방문자가 월/주 단위로 조회.

### 데이터 모델
| 필드 | 설명 |
|---|---|
| title | 일정 제목 |
| start_at / end_at | 시작·종료 일시 (종일 이벤트 지원) |
| location | 장소 (선택) |
| description | 상세 설명 |
| category | 분류 (선택 — 세미나/행사/방문 등) |
| created_by | admin 계정 |

### 사용자 흐름
- **admin**: 등록/수정/삭제. About 문서에 따르면 "임원진 회의로 일정 확정 → 담당자(admin)가 캘린더에 등록"하는 오프라인 선행 절차가 있음.
- **전체(비로그인 포함)**: 조회만 (월/주 뷰 전환, 특정 날짜 클릭 시 해당일 이벤트 상세).

### Rhymix 구현 메모
표준 게시판 모듈로는 캘린더 UI를 제공하지 않음. `kitel_rental_*`처럼 **독립 테이블 + 커스텀 모듈**로 구현하거나, Rhymix 애드온 생태계에 캘린더류가 있는지 확인 필요.

### 열린 질문
- 매주 정기모임처럼 **반복 일정**을 지원해야 하나요, 아니면 매번 개별 등록으로 충분한가요?
- 카테고리별 색상 구분 등 시각적 분류가 필요한가요?
- 이벤트에 신청/RSVP 같은 상호작용이 앞으로 필요할 가능성이 있나요? (지금 당장은 아니어도 데이터 구조에 여지를 둘지 판단하는 데 필요)

## 2. Kitel News (공지사항)

**목적**: 동아리 소식을 대내외에 알리되, 상세 내용은 회원 전용으로 보호.

### 데이터 모델
표준 게시판 필드(제목/본문/첨부파일/작성일) + 카테고리 3종: **동아리 내 경사 / 최근 진행 행사 보고 / 기업방문·세미나 등 일정 공고**. 작성자는 항상 admin.

### 사용자 흐름
- **비로그인 방문자**: 목록(제목·카테고리·날짜)까지만 조회. 글 클릭 시 다음/네이버 카페 스타일의 "로그인 후 확인 가능" 잠금 안내.
- **준회원 이상 로그인 회원**(가입대기 제외): 본문 전체 열람.
- **admin**: 작성/수정/삭제.

### Rhymix 구현 메모
Rhymix(XE 계열) 게시판 모듈의 module_grants가 **"목록 보기"와 "본문 읽기"를 별도 권한으로 분리 지정**할 수 있다면, 커스텀 개발 없이 grants 설정만으로 해결 가능. 개발 착수 시 가장 먼저 검증할 부분.

### 열린 질문
- 비로그인 사용자가 잠긴 글을 클릭했을 때 보여줄 안내 문구/모달 디자인 (디자이너 협업 필요, 기능 명세와는 별개)

## 3. Study > 자료실

**목적**: 현재 NAS Drive가 담당하는 "정회원 전용 자유 자료 공유"를 홈페이지로 이관해 활성화.

### 데이터 모델
| 대상 | 필드 |
|---|---|
| 폴더 | 폴더명, 상위폴더, 생성자, 생성일 |
| 파일 | 파일명, 소속 폴더, 업로더, 업로드일, 용량, 다운로드 수 |

### 사용자 흐름
- **정회원 이상**: 폴더 자유 생성(고정 카테고리 없음, [new-site-ia.md](new-site-ia.md) 2-4 확정 사항), 파일 업로드/다운로드.
- 그 외 등급: 접근 불가.

### Rhymix 구현 메모
표준 게시판의 첨부파일 기능만으로는 "폴더 트리 탐색" UX를 만들기 어려움 — 파일 브라우저형 UI가 필요해 **커스텀 모듈** 또는 파일 관리형 애드온 검토 필요. NAS Drive 이관 시 원 업로더를 홈페이지 회원과 매칭하기 어려운 파일은 "관리자 일괄 업로드"로 처리하는 방식 검토.

### 열린 질문
- 파일/폴더 **삭제·이동 권한**: 본인이 올린 것만 가능한가요, 정회원이면 누구나(NAS Team Folder처럼 공동 관리) 가능한가요?
- 회원 1인당 또는 전체 저장 용량 제한이 필요한가요? (서버 용량 정책과 연결)
- 이미지/PDF **미리보기** 지원이 필요한가요, 다운로드만으로 충분한가요?

## 4. Study > 과제게시판

**목적**: 준회원의 1년간 선발 과정에서 필요한 과제(세미나 과제, 품평회 과제 등)를 출제·제출·현황 관리.

### 데이터 모델
| 테이블 | 필드 |
|---|---|
| assignment(과제) | 제목, 설명, 제출기한, 제출 양식 정의(텍스트/파일첨부 등 필드 구성), 공개여부, 출제자(기술부원), 생성일 |
| submission(제출물) | 과제 참조, 제출자(준회원), 제출 내용/첨부파일, 제출일시, 상태(제출/미제출/재제출요청 등) |

### 사용자 흐름
- **기술부**: 과제 생성(제목/설명/기한/제출 양식 구성) → 게시 → **제출현황 대시보드**에서 준회원별 제출여부를 매트릭스(과제 × 준회원)로 확인, 필터(과제별/준회원별/기간별) → 필요 시 채점/피드백 입력.
- **준회원**: 과제 목록 확인 → 제출 폼 작성 → 제출 → **본인 제출물만** 재조회 가능(다른 준회원 것은 열람 불가).
- **정회원 이상**: 과제 목록 + 전체 제출물 열람 가능(읽기 전용, [new-site-ia.md](new-site-ia.md) 확정 사항 3번). 사이트 내 피드백 기능은 두지 않음(멘토-멘티 등 오프라인/개인 연락으로 처리).

### Rhymix 구현 메모
"준회원은 본인 글만, 정회원은 전체 열람"은 표준 게시판 grants(게시판 단위 권한)만으로는 세분화하기 어려움. XE/Rhymix의 **"비밀글"(작성자+관리자만 열람) 기능을 응용**해 준회원 제출물은 항상 비밀글로 강제 등록하고, 정회원 이상을 "관리자에 준하는 열람 권한"으로 별도 grant하는 방식이 가능한지가 관건 — 실제 Rhymix 게시판 grants API/코드를 개발 착수 시점에 조사 필요. 대시보드(과제 × 준회원 매트릭스)는 표준 게시판 목록 뷰로는 안 되므로 커스텀 화면 필요.

### 열린 질문
- **재제출(수정) 허용 여부**와 마감기한 이후 제출 처리(지각 표시를 둘지, 아예 차단할지)
- 채점/평가 결과(점수, 합격여부 등)를 사이트에 **기록으로 남길지**, 아니면 제출 여부 확인용으로만 쓸지
- 과제 유형(세미나 과제/품평회 과제 등)을 **카테고리로 구분**해서 관리해야 하나요?

## 5. Study > 작품전시회 게시판 (구 축제게시판)

**목적**: 연 1회 작품전시회 출품작을 팜플렛처럼 한눈에 보여주는 갤러리. 외부 방문객(올해는 기업 관계자 포함)도 열람.

### 데이터 모델
고정 양식: **작품명(텍스트) / 작품 사진(이미지) / 간단설명(글자수 제한) / 제안서(파일첨부)** + 상태값(작성중/검토중/승인/공개).

### 사용자 흐름
1. **정회원**이 고정 양식에 맞춰 작성 → 제출(상태: 검토중)
2. **기술부**가 조사·작품 파악·양식 확인 (필요 시 보완 요청)
3. **admin**이 최종 승인 → 공개 전환 ([new-site-ia.md](new-site-ia.md) 확정 사항 2번)
4. **전체(비로그인 포함)**: 승인된 작품만 갤러리 형태(그리드 카드: 사진+작품명+간단설명)로 열람, 클릭 시 상세.
5. 사이트 내 댓글/피드백 기능 없음 — 실제 질의응답은 전시회 현장에서 오프라인으로 진행.

### Rhymix 구현 메모
표준 게시판 + 확장변수(고정 필드)로 데이터는 담을 수 있으나, "승인 전 비공개 → 승인 후 공개"라는 **발행 워크플로우(상태 전이)** 는 표준 기능이 아니라 커스텀 처리 필요(상태 필드 + 노출 조건 분기). 갤러리형 카드 리스트는 커스텀 스킨(list style) 필요.

### 열린 질문
- 작품 **사진 최대 장수**, **간단설명 글자수 제한**의 구체적 수치
- **제안서 파일도 비로그인 방문자에게 공개**되나요, 아니면 사진/설명만 공개하고 제안서는 회원 전용인가요?
- 기술부가 검토 중 보완을 요청했을 때 **정회원에게 어떻게 알릴지**(사이트 내 코멘트/상태 표시 vs 개인 연락)
- 과거 연도 출품작들을 나중에 이관한다면, **연도별 아카이브 열람(필터)**이 필요한가요?

## 6. Study > 세미나 게시판

**목적**: 발표자(정회원)가 세미나 자료를 남기고, 다음 발표를 준비하는 정회원이 참고하는 아카이브.

### 데이터 모델
세미나 제목, 발표자(정회원), 발표일자, 발표자료(첨부파일), 참고자료(추가 파일/링크, 선택).

### 사용자 흐름
- **정회원**: 작성(자신이 진행한/진행할 세미나 자료 업로드).
- **준회원 이상**: 열람만.

### Rhymix 구현 메모
표준 게시판 + 확장변수(발표자/발표일 필드) 정도로 충분해 보임. 별도 커스텀 개발 필요성 낮음.

### 열린 질문
- 주제별 **카테고리 분류**가 필요한가요, 아니면 시간순 목록으로 충분한가요?

## 7. Study > 공유 게시판

**목적**: 개인 프로젝트, 스터디 자료, 채용·인턴 정보 등을 자유롭게 공유하는 내부 커뮤니티. 졸업생 스폰서의 "기술 계승" 요청이 계기. X-File/Drone/RaffeeMachine/IOelec 등 기존 개별 프로젝트 페이지의 역할도 흡수 예정.

### 현재 범위
운영 세부사항 미정 확정([new-site-ia.md](new-site-ia.md) 확정 사항). **우선 표준 게시판 형태(정회원 read/write)로 빈 상태로 오픈**하고, 세부 기획(카테고리 구성 등)은 추후 별도 논의.

### 열린 질문
- 이 문서 범위에서는 최소 스펙(표준 게시판)으로 두고, 세부 설계는 별도 라운드에서 다시 다뤄도 괜찮을까요?

## 8. 기타 > 건의사항

**목적**: 정회원이 운영진에게 의견을 전달하는 비공개 채널.

### 데이터 모델
제목, 본문, 익명여부(체크박스).

### 사용자 흐름
- **정회원**: 작성(준회원은 작성 불가). 본인 글은 본인만 재조회 가능.
- **임원진**: 전체 글 열람 가능.

### 익명 처리 확정
**임원진에게도 익명 처리됨** — 임원진도 화면상 작성자를 "익명"으로만 보게 됨.

**채택**: 어뷰징(도배, 욕설 등) 방지를 위해 **DB에는 작성자를 남기되 화면(UI)에서는 임원진에게도 항상 숨김** 처리. admin의 로그 조회 기능으로만 필요시 확인 가능.

### Rhymix 구현 메모
표준 게시판. "익명" 체크 시 작성자 표시란을 항상 "익명"으로 대체(임원진 포함 모든 열람자에게 동일하게 적용).

## 9. 기타 > Contact Us

**확정**: 방문자가 입력하는 문의 폼이 아니라, admin이 연락처 정보(주소·이메일·SNS 링크 등)를 관리하는 **단순 정적 안내 페이지**. 기능 명세상으로는 About 하위 정적 페이지들과 동일하게 admin 작성/수정, 전체공개 읽기 외에 별도 로직 없음. 상세 UI/레이아웃은 디자이너 영역.

## 10. 기타 > 기자재 대여 시스템

기존 분석([xeadmin-site-analysis.md](xeadmin-site-analysis.md) 6번) 및 IA 문서에서 이미 다룬 대로 **기존 구현을 그대로 유지**, 신규 사이트에서는 "기타" 메뉴 하위에 진입점만 배치. 인증 어댑터를 Rhymix 세션 체계로 교체하는 작업만 별도 진행 예정 — 이번 문서의 상세 명세 범위에서는 제외.

## 11. About 하위 정적 페이지 (키텔소개/연혁/활동/연구분야/임원진소개/회칙 등)

정적 HTML 콘텐츠(admin 작성/수정, 전체공개 읽기)로 특별한 데이터 모델이 필요 없음. 디자인 확정 후 콘텐츠 문구만 정리하면 되는 수준이라 이번 "상세 기능 명세" 범위에서는 제외하고, 추후 콘텐츠 정리 단계에서 다룸.
