## 1. 캘린더 (About > 일정)

**목적**: admin이 확정된 행사 일정을 등록하면 전 방문자가 월/주 단위로 조회.

### 데이터 모델
| 필드 | 설명 |
|---|---|
| title | 일정 제목 |
| start_at / end_at | 시작·종료 일시 (종일 이벤트 지원) |
| location | 장소 (선택) |
| description | 상세 설명 |
| category | 분류 (선택 — 세미나/행사/방문 등) |
| created_by | admin 계정 |

### 사용자 흐름
- **admin**: 등록/수정/삭제. About 문서에 따르면 "임원진 회의로 일정 확정 → 담당자(admin)가 캘린더에 등록"하는 오프라인 선행 절차가 있음.
- **전체(비로그인 포함)**: 조회만 (월/주 뷰 전환, 특정 날짜 클릭 시 해당일 이벤트 상세).

### ✅✅ 구현 완료 (2026-08-19)
`modules/calendar`로 실제 커스텀 모듈을 만들어 로컬 Rhymix에 설치·검증까지 마침 (소스는 [custom_modules/calendar](../custom_modules/calendar)에 보관). 번들 모듈에 캘린더류가 없어 가설대로 커스텀 개발이 필요했고, 표준 모듈 스캐폴드(`conf/module.xml` + `calendar.class/model/view/controller.php`(+admin) + `schemas/` + `queries/` + `skins/default/`)로 구현함.

- **공개 화면**: 월 그리드, 이전/다음 달 이동, 오늘 날짜 강조, 날짜별 이벤트 표시 — 전체공개(비로그인 포함) 조회
- **관리자 화면**: 일정 목록/등록/수정/삭제, admin 전용
- **스킨 지원**: `skins/default/skin.xml` + `list.html`로 다른 게시판과 동일한 방식의 스킨 교체 가능 — 디자이너가 새 스킨 폴더만 추가하면 됨
- **권한 관리**: module.xml에 `list`(조회)/`manage`(등록·수정·삭제) 그랜트를 선언했더니 게시판과 동일한 권한 설정 화면이 자동 생성됨(`getModuleGrantHTML` 공용 로직 재사용) — 나중에 "일정 관리" 권한을 임원진 등 특정 그룹에 위임하는 것도 코드 수정 없이 가능

⚠️ **트러블슈팅 기록**: "메뉴 추가" UI로 신규 모듈 타입의 메뉴를 만들면 `xe_modules` 행과 메뉴만 생성되고 **DB 스키마 설치(`moduleInstall()`)는 자동으로 실행되지 않음** — `module=install&act=procInstallAdminInstall&module_name=calendar` 액션을 별도로 호출해야 `schemas/*.xml`이 실제 테이블로 만들어짐. 새 커스텀 모듈을 추가할 때마다 이 스텝이 필요.

### 남은 질문 (기능 확장 시 고려)
- 매주 정기모임처럼 **반복 일정**을 지원해야 하나요, 아니면 매번 개별 등록으로 충분한가요?
- 카테고리별 색상 구분 등 시각적 분류가 필요한가요?
- 이벤트에 신청/RSVP 같은 상호작용이 앞으로 필요할 가능성이 있나요?

## 2. Kitel News (공지사항)

**목적**: 동아리 소식을 대내외에 알리되, 상세 내용은 회원 전용으로 보호.

### 데이터 모델
표준 게시판 필드(제목/본문/첨부파일/작성일) + 카테고리 3종: **동아리 내 경사 / 최근 진행 행사 보고 / 기업방문·세미나 등 일정 공고**. 작성자는 항상 admin.

### 사용자 흐름
- **비로그인 방문자**: 목록(제목·카테고리·날짜)까지만 조회. 글 클릭 시 다음/네이버 카페 스타일의 "로그인 후 확인 가능" 잠금 안내.
- **준회원 이상 로그인 회원**(가입대기 제외): 본문 전체 열람.
- **admin**: 작성/수정/삭제.

### ✅ Rhymix 구현 검증 완료
로컬 개발 환경(`test_board`)에서 실제 확인함: 게시판 관리 > 권한 관리 화면에 **"목록"과 "열람"이 완전히 분리된 권한 항목**으로 존재하고, 각각 모든 방문자/로그인 사용자/선택 그룹 소속 회원 등으로 독립 지정 가능. **커스텀 개발 없이 grants 설정만으로 해결됨.** "목록"=모든 방문자, "열람"=선택 그룹(준회원 이상)으로 설정하면 됨. ([dev-environment.md](dev-environment.md) 검증 기록 참고)

### 열린 질문
- 비로그인 사용자가 잠긴 글을 클릭했을 때 보여줄 안내 문구/모달 디자인 (디자이너 협업 필요, 기능 명세와는 별개)

## 3. Study > 자료실

**목적**: 현재 NAS Drive가 담당하는 "정회원 전용 자유 자료 공유"를 홈페이지로 이관해 활성화.

### 데이터 모델
| 대상 | 필드 |
|---|---|
| 폴더 | 폴더명, 상위폴더, 생성자, 생성일 |
| 파일 | 파일명, 소속 폴더, 업로더, 업로드일, 용량, 다운로드 수 |

### 사용자 흐름
- **정회원 이상**: 폴더 자유 생성(고정 카테고리 없음, [new-site-ia.md](new-site-ia.md) 2-4 확정 사항), 파일 업로드/다운로드.
- 그 외 등급: 접근 불가.

### ✅✅ 구현 완료 (2026-08-19)
`modules/archive`(mid=`storage`)로 실제 커스텀 모듈을 만들어 로컬 Rhymix에 설치·검증까지 마침 (소스는 [custom_modules/archive](../custom_modules/archive)). 캘린더와 같은 표준 모듈 스캐폴드로 구현.

- **폴더 트리 탐색**: 루트부터 하위 폴더까지 자유롭게 생성·진입, 브레드크럼(전체 / 상위 / 현재) 표시
- **파일 업로드/다운로드**: 일반 multipart 폼 업로드, 다운로드는 컨트롤러를 통해 스트리밍(실제 저장 경로는 `.htaccess`로 직접 접근 차단 — `Require all denied`, `rental_dev/app`와 동일한 패턴)
- **삭제**: 파일 단건 삭제, 폴더는 하위 폴더·파일까지 재귀 삭제(NAS Team Folder처럼 정회원 누구나 공동 관리하는 방식으로 결정)
- **권한**: "조회/다운로드"·"폴더 생성·파일 업로드·삭제" 두 grant를 정회원 이상 그룹(정회원·특별회원·임원진·정보부·기술부)으로 설정 — 캘린더와 동일하게 게시판형 권한 화면 재사용
- 폴더 생성 → 진입 → 파일 업로드 → 다운로드(파일명·내용 확인) → 파일 삭제 → 폴더 삭제까지 전 과정 실제로 테스트해 확인함

⚠️ **트러블슈팅 기록(캘린더에도 소급 적용)**: 다운로드·삭제처럼 단순 링크(`<a href>`)로 트리거하는 컨트롤러 액션은 기본적으로 GET을 허용하지 않아 "이 요청에 사용할 수 없는 HTTP 메소드입니다" 오류가 남. `module.xml`의 해당 action에 `method="GET|POST"`를 명시해야 함(Rhymix 코어의 `file` 모듈 `procFileDownload`도 동일 패턴). 캘린더의 `procCalendarAdminDeleteEvent`도 같은 문제가 있어 함께 수정함.

### 남은 질문 (확장 시 고려)
- 회원 1인당 또는 전체 저장 용량 제한 필요 여부 (서버 용량 정책과 연결, 현재는 무제한)
- 이미지/PDF **미리보기** 지원 필요 여부 (현재는 다운로드만)
- NAS Drive 기존 자료 이관 시, 원 업로더를 홈페이지 회원과 매칭 못 하는 파일은 "관리자 일괄 업로드"로 처리

## 4. Study > 과제게시판

**목적**: 준회원의 1년간 선발 과정에서 필요한 과제(세미나 과제, 품평회 과제 등)를 출제·제출·현황 관리.

### 데이터 모델
| 테이블 | 필드 |
|---|---|
| assignment(과제) | 제목, 설명, 제출기한, 제출 양식 정의(텍스트/파일첨부 등 필드 구성), 공개여부, 출제자(기술부원), 생성일 |
| submission(제출물) | 과제 참조, 제출자(준회원), 제출 내용/첨부파일, 제출일시, 상태(제출/미제출/재제출요청 등) |

### 사용자 흐름
- **기술부**: 과제 생성(제목/설명/기한/제출 양식 구성) → 게시 → **제출현황 대시보드**에서 준회원별 제출여부를 매트릭스(과제 × 준회원)로 확인, 필터(과제별/준회원별/기간별) → 필요 시 채점/피드백 입력.
- **준회원**: 과제 목록 확인 → 제출 폼 작성 → 제출 → **본인 제출물만** 재조회 가능(다른 준회원 것은 열람 불가).
- **정회원 이상**: 과제 목록 + 전체 제출물 열람 가능(읽기 전용, [new-site-ia.md](new-site-ia.md) 확정 사항 3번). 사이트 내 피드백 기능은 두지 않음(멘토-멘티 등 오프라인/개인 연락으로 처리).

### ⚠️ 방향 수정: 게시판 "상담 기능" 재사용은 실제로는 부적합했음
처음에는 board 모듈의 상담 기능으로 해결된다고 봤으나(캘린더/자료실 검증 당시), **실제로 board 모듈을 만들어보니 문제가 발견됨**: 상담 기능은 "관리 권한이 없는 회원에게는 본인이 쓴 글만" 보여주는 기능이라, 기술부가 올린 과제 공지 글도 준회원 본인이 작성한 게 아니므로 **준회원에게는 아예 안 보이게 됨**. 즉 "출제자가 공개로 올린 글 + 제출자만 보는 비공개 제출물"이라는, 서로 다른 두 종류의 가시성이 섞인 요구사항에는 상담 기능(단일 종류 콘텐츠 전제)이 맞지 않았음.

### ✅✅ 구현 완료 (2026-08-19) — 별도 모듈로 재구축
기존에 만들었던 `assignment` 게시판(빈 상태였음, 데이터 없음 확인 후 삭제)을 대신해 **`modules/homework`를 처음부터 구조화된 데이터 모델로 새로 만듦** (소스: [custom_modules/homework](../custom_modules/homework), mid=`homework`, 메뉴명은 그대로 "과제게시판" 유지).

**데이터 모델을 스펙 그대로 두 테이블로 분리**: `homework_task`(과제: 제목/설명/마감일/출제자) + `homework_submission`(제출물: 과제 참조/제출자/내용/첨부파일/지각여부). 이 구조 덕분에 "출제자 공개글 + 제출자 비공개 제출물"이 자연스럽게 분리됨.

**권한 4종** (게시판형 grants 화면 재사용, 캘린더·자료실과 동일 패턴):
| grant | 의미 | 설정값 |
|---|---|---|
| list | 과제 목록/상세 열람 | 준회원 이상 |
| submit | 과제 제출 | 준회원만 |
| view_all | 전체 제출물 열람 | 정회원 이상 |
| create | 과제 출제·관리(대시보드 포함) | 기술부만 |

**화면 구성**:
- 공개: 과제 목록(내 제출 상태 뱃지 표시) → 과제 상세(준회원: 제출/재제출 폼, 정회원 이상: 전체 제출자 목록+다운로드)
- 관리자(기술부): 과제 관리(등록/수정/삭제), **제출현황 대시보드(과제 × 준회원 매트릭스, 준회원 그룹 전원을 행으로, 제출 여부·지각 여부·제출일을 셀로 표시)**, 권한 관리
- 첨부파일은 자료실과 동일하게 `files/attach/homework/{module_srl}/`에 저장 + `.htaccess` 차단, 다운로드는 본인 또는 view_all 권한자만 가능하도록 컨트롤러에서 이중 체크

**결정한 것들** (그동안의 열린 질문 확정):
- **재제출**: 허용. 같은 과제에 다시 제출하면 기존 제출물을 덮어씀(upsert), 제출일도 최신으로 갱신
- **마감 후 제출**: 차단하지 않고 **지각으로 표시만** 함(대시보드·상세 화면 모두에 "지각" 뱃지)
- **채점/평가 결과**: 이번 구현 범위에서는 제외 — 스펙대로 "제출 여부 확인용"으로만 사용, 점수/합격여부 필드는 만들지 않음
- **과제 유형 카테고리**: 이번 구현 범위에서는 제외(과제 수가 적을 때는 목록만으로 충분하다고 판단, 필요해지면 `homework_task`에 category 컬럼 추가하면 됨)

전 과정(과제 출제 → 목록 노출 → 제출 → 재제출 시 upsert 확인 → 첨부파일 다운로드 권한 이중 체크 → 대시보드 매트릭스가 준회원 그룹 전원 기준으로 정확히 집계되는지)을 실제로 테스트해 확인함.

## 5. Study > 작품전시회 게시판 (구 축제게시판)

**목적**: 연 1회 작품전시회 출품작을 팜플렛처럼 한눈에 보여주는 갤러리. 외부 방문객(올해는 기업 관계자 포함)도 열람.

### 데이터 모델
고정 양식: **작품명(텍스트) / 작품 사진(이미지) / 간단설명(글자수 제한) / 제안서(파일첨부)** + 상태값(작성중/검토중/승인/공개).

### 사용자 흐름
1. **정회원**이 고정 양식에 맞춰 작성 → 제출(상태: 검토중)
2. **기술부**가 조사·작품 파악·양식 확인 (필요 시 보완 요청)
3. **admin**이 최종 승인 → 공개 전환 ([new-site-ia.md](new-site-ia.md) 확정 사항 2번)
4. **전체(비로그인 포함)**: 승인된 작품만 갤러리 형태(그리드 카드: 사진+작품명+간단설명)로 열람, 클릭 시 상세.
5. 사이트 내 댓글/피드백 기능 없음 — 실제 질의응답은 전시회 현장에서 오프라인으로 진행.

### 🔍 Rhymix 구현 검증 — 부분 확인
표준 게시판 + 확장변수(고정 필드)로 데이터는 담을 수 있음. 게시판 설정에 문서 작성 시 선택하는 **"상태: 공개/비밀"** 필드가 이미 내장되어 있어, "검토중"을 이 비밀 상태로, admin 승인 시 공개로 전환하는 식으로 재사용할 여지가 있어 보이나 — 비밀 상태의 정확한 열람 범위(작성자만인지, 상담 기능과 연동되는지)는 실제 문서를 만들어 추가 확인이 필요함. 갤러리형 카드 리스트(사진+작품명+간단설명)는 표준 목록 스킨으로 안 되므로 **커스텀 스킨(list style) 필요** — 이 부분은 가설대로 확정.

### 열린 질문
- 작품 **사진 최대 장수**, **간단설명 글자수 제한**의 구체적 수치
- **제안서 파일도 비로그인 방문자에게 공개**되나요, 아니면 사진/설명만 공개하고 제안서는 회원 전용인가요?
- 기술부가 검토 중 보완을 요청했을 때 **정회원에게 어떻게 알릴지**(사이트 내 코멘트/상태 표시 vs 개인 연락)
- 과거 연도 출품작들을 나중에 이관한다면, **연도별 아카이브 열람(필터)**이 필요한가요?

## 6. Study > 세미나 게시판

**목적**: 발표자(정회원)가 세미나 자료를 남기고, 다음 발표를 준비하는 정회원이 참고하는 아카이브.

### 데이터 모델
세미나 제목, 발표자(정회원), 발표일자, 발표자료(첨부파일), 참고자료(추가 파일/링크, 선택).

### 사용자 흐름
- **정회원**: 작성(자신이 진행한/진행할 세미나 자료 업로드).
- **준회원 이상**: 열람만.

### Rhymix 구현 메모
표준 게시판 + 확장변수(발표자/발표일 필드) 정도로 충분해 보임. 별도 커스텀 개발 필요성 낮음.

### 열린 질문
- 주제별 **카테고리 분류**가 필요한가요, 아니면 시간순 목록으로 충분한가요?

## 7. Study > 공유 게시판

**목적**: 개인 프로젝트, 스터디 자료, 채용·인턴 정보 등을 자유롭게 공유하는 내부 커뮤니티. 졸업생 스폰서의 "기술 계승" 요청이 계기. X-File/Drone/RaffeeMachine/IOelec 등 기존 개별 프로젝트 페이지의 역할도 흡수 예정.

### 현재 범위
운영 세부사항 미정 확정([new-site-ia.md](new-site-ia.md) 확정 사항). **우선 표준 게시판 형태(정회원 read/write)로 빈 상태로 오픈**하고, 세부 기획(카테고리 구성 등)은 추후 별도 논의.

### 열린 질문
- 이 문서 범위에서는 최소 스펙(표준 게시판)으로 두고, 세부 설계는 별도 라운드에서 다시 다뤄도 괜찮을까요?

## 8. 기타 > 건의사항

**목적**: 정회원이 운영진에게 의견을 전달하는 비공개 채널.

### 데이터 모델
제목, 본문, 익명여부(체크박스).

### 사용자 흐름
- **정회원**: 작성(준회원은 작성 불가). 본인 글은 본인만 재조회 가능.
- **임원진**: 전체 글 열람 가능.

### 익명 처리 확정
**임원진에게도 익명 처리됨** — 임원진도 화면상 작성자를 "익명"으로만 보게 됨.

**채택**: 어뷰징(도배, 욕설 등) 방지를 위해 **DB에는 작성자를 남기되 화면(UI)에서는 임원진에게도 항상 숨김** 처리. admin의 로그 조회 기능으로만 필요시 확인 가능.

### ✅ Rhymix 구현 검증 완료
게시판 정보 > 고급 설정에 **"익명 사용"** 옵션이 내장되어 있고, 그 안에 "관리자 익명 제외"(관리 권한자에게는 실명 노출) 체크박스가 별도로 존재함. 이 체크박스를 **꺼두면** 관리 권한이 있는 회원(임원진 포함)에게도 "익명"으로 표시됨 — 요구사항과 정확히 일치. **커스텀 개발 불필요, 표준 게시판 설정으로 해결.** DB에는 작성자(member_srl)가 그대로 남으므로 admin이 필요시 DB/로그로 추적 가능한 것도 요구사항과 일치.

## 12. 메인 페이지 (홈)

**목적**: 스크롤에 따라 여러 섹션(히어로 → 최신 소식 → 다가오는 일정 → 작품전시회 하이라이트 등)이 순서대로 드러나는 원페이지 구성. 각 섹션은 **정적 큐레이션이 아니라 각 게시판/모듈의 최신 데이터를 자동으로 끌어오는 방식**으로 확정됨(2026-08-19). 참고 디자인 레퍼런스: [designer-brief.md §7](designer-brief.md).

### 아키텍처: 정적 페이지가 아니라 "위젯 페이지"
메인 화면이 여러 모듈의 데이터를 한 화면에 모아 보여줘야 하므로, 단일 `page` 모듈이 아니라 Rhymix의 **위젯 페이지**(메뉴 타입 중 하나로 이미 확인됨)로 구성. 위젯 페이지는 여러 위젯 블록을 순서대로 배치하는 구조라, "섹션별 순서 변경/노출 여부 조정"이 **코드 수정 없이 관리자 화면에서** 가능해짐 — 유지보수 측면에서 유리.

### 섹션별 구현 방식

| 섹션 | 방식 | 비고 |
|---|---|---|
| 최신 Kitel News 미리보기 | **Rhymix 기본 제공 "Content 위젯" 재사용** | `widgets/content`가 이미 "지정 게시판(mid)에서 최신 N개 문서를 가져와 표시"하는 기능을 완비하고 있음(정렬 기준, 개수, 썸네일, 마크업 스타일까지 관리자 설정 화면에서 조정 가능) — **커스텀 개발 불필요**, mid=news로 설정만 하면 됨 |
| 작품전시회 하이라이트 | **Content 위젯 재사용** | 동일한 이유로 mid=exhibition 설정만으로 가능. 다만 "승인된 것만" 필터가 Content 위젯 기본 기능 범위 밖이면 소폭 커스터마이징 필요 — §5 승인 워크플로우 구현 시 함께 확인 |
| 다가오는 일정 미리보기 | **신규 소형 위젯 필요** | Content 위젯은 표준 문서(게시판) 대상이라 캘린더 커스텀 테이블(`rx_calendar_event`)은 지원 못 함. `widgets/upcoming_events` 같은 이름으로 소형 위젯 신규 제작 필요(오늘 이후 이벤트 N개를 CalendarModel로 조회해 출력) — 이미 만든 캘린더 모듈의 model을 그대로 재사용하므로 개발량은 적음 |
| 히어로 배너 | **신규 소형 위젯 필요, 전환(캐러셀) 없음** | 여러 장 자동 전환은 하지 않지만, **admin이 문구/이미지를 바꿀 수 있어야** 함(유지보수 목적으로 확정). Rhymix 위젯은 `conf/info.xml`의 `extra_vars` 선언만으로 관리자 설정 폼이 자동 생성되므로(`content` 위젯에서 실물 확인), 헤드라인/서브텍스트/배경이미지/CTA 링크를 extra_vars로 선언한 소형 위젯 하나면 별도 관리자 화면(admin view/controller)을 따로 만들 필요 없이 해결됨 |

### 결론
애초 우려했던 것보다 백엔드 영향은 제한적임: **신규 개발이 필요한 건 "다가오는 일정" 위젯과 "히어로 배너" 위젯 2개뿐**이고, 둘 다 게시판 신설 수준이 아니라 캘린더보다도 훨씬 가벼운 소형 위젯. 나머지 미리보기 섹션은 Rhymix 기본 제공 Content 위젯 설정만으로 해결됨. 스크롤 시 섹션이 드러나는 애니메이션 자체는 순수 프론트엔드(CSS/JS, IntersectionObserver 등) 영역이라 백엔드와 무관.

### 열린 질문
- 히어로 배너 위젯의 정확한 필드 구성(헤드라인/서브텍스트/배경이미지/CTA 텍스트·링크 외 추가 필드 필요 여부)
- "다가오는 일정" 미리보기에 노출할 이벤트 개수, 오늘 지난 이벤트 처리 방식
- 각 섹션(소식/일정/전시회 하이라이트) 노출 개수와 순서 최종 확정
