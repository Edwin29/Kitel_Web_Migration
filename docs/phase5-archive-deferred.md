# Phase 5 — 자료실 구현 보류

**상태: DEFERRED — PRODUCT / MIGRATION POLICY UNRESOLVED** (2026-09-30)

이번 퍼블리싱 사이클에서는 Archive UI, 기능, 권한, 데이터 이관을 구현하지 않는다. `custom_modules/archive`의 기존 백엔드는 보존한다. Phase 6 Homework는 자료실 정책 결정과 독립적으로 진행할 수 있다. 이 문서는 기존 handoff의 Phase 5 구현 지시보다 이후에 결정된 보류 상태를 기록한다.

## 운영 배경과 보류 이유

기존 자료실은 정회원들이 NAS Drive의 공용 폴더와 파일을 함께 사용하는 방식이다. NAS/DSM/LDAP 권한과 홈페이지 회원 등급·그룹은 직접 연동되지 않는다. 홈페이지에서는 정회원인데 NAS 접근 권한이 없거나, 홈페이지 권한이 변경된 뒤에도 NAS 권한이 남을 수 있다. 회원 권한을 두 곳에서 따로 관리해야 하므로 자료실을 홈페이지 회원 체계로 통합하려는 목적이 있다.

공용 파일을 여러 사람이 직접 바꾸는 방식은 파일 교체·이동·삭제가 모든 이용자에게 즉시 영향을 주며, 공동 의사와 무관한 변경이나 실수가 생길 수 있다. 변경자 추적과 이전 버전 복구도 현재 정책상 명확하지 않다. 이 운영 방식을 웹에 그대로 복제할지 먼저 결정해야 한다.

기존 NAS 자료는 이미 규모가 크고 폴더 구조도 자리 잡았다. [NAS 실사 기록](roadmap.md)에 따르면 이관 후보 공유 폴더 합계는 약 311GB다. 따라서 이관 범위와 기존 폴더 구조를 결정하기 전에 자료실 UI를 확정하면 재작업 가능성이 높다.

## 현재 repository 백엔드

`custom_modules/archive`에는 폴더 목록·하위 폴더 탐색·breadcrumb, 파일 목록, 폴더 생성, 파일 업로드·다운로드, 파일 및 하위 내용을 포함한 폴더 삭제가 구현되어 있다. `list`와 `manage` grant로 조회·다운로드와 생성·업로드·삭제를 구분하며, 현재 개발 환경 설정은 정회원 이상에게 두 권한을 부여한 것으로 기존 문서에 기록되어 있다. 이 구현과 권한 모델은 최종 제품 정책으로 확정된 것이 아니다. 이번 보류 작업에서는 백엔드, skin, grants, 데이터베이스, NAS 연결을 변경하지 않는다.

## 재개 전에 결정할 사항

| 영역 | 결정할 질문과 후보 |
|---|---|
| 이관 범위 | 전체, 핵심 폴더, 최근·활성 자료, 신규 자료만 웹에서 관리하고 NAS는 legacy로 유지, 또는 과거 자료를 읽기 전용으로 이관할지 결정한다. 개인정보가 포함될 수 있는 폴더의 취급도 정한다. |
| 폴더 구조 | NAS 구조를 1:1 유지할지, 정리하거나 웹 사용 목적에 맞게 재분류할지, legacy 구조와 신규 구조를 분리할지 결정한다. |
| 권한 | 조회, 다운로드, 업로드, 폴더 생성, 본인·타인 파일 수정, 이동, 이름 변경, 교체, 파일 삭제, 폴더 삭제를 역할별로 어디까지 허용할지 결정한다. 현재 `manage` 하나로 묶인 동작을 유지할지도 결정한다. |
| 공용 파일 수정 | 직접 덮어쓰기, 새 버전 업로드, version history, 교체 권한을 가진 역할, 일반 회원의 파일 추가만 허용 중 어떤 방식을 채택할지 결정한다. |
| 삭제·복구 | 즉시 삭제, soft delete, 휴지통, 관리자 최종 삭제, 보관 기간과 복구 가능 여부를 결정한다. |
| 활동 기록 | 업로더, 수정자·시각, 이동, 삭제·복구, 버전 변경 이력을 기록·열람할 필요가 있는지 결정한다. |

권한 모델의 **검토 후보**는 정회원에게 조회·다운로드·업로드·본인 파일 관리·새 버전 제출을, 자료실 관리자 또는 임원진에게 폴더 구조·이동·이름 변경·공용 자료 교체·삭제·복구를, Admin에게 전체 관리를 부여하는 것이다. 이는 확정 정책이 아니다.

또 다른 **검토 후보**는 Active Library와 Legacy Archive의 분리다. Active Library는 현재 사용하는 자료의 검색·업로드·버전·권한을 다루고, Legacy Archive는 과거 NAS 폴더 구조를 최대한 보존한 읽기 전용 영역으로 운영한다. 필요할 때 자료를 Active Library로 승격할 수 있다. 두 영역을 만들지 여부와 승격 절차 역시 미정이다.

## Phase 5 재개 조건

NAS 이관 범위, 폴더 구조 유지 여부, 역할별 권한, 공용 파일 수정 방식, 삭제·복구 정책, 버전 이력 필요 여부, 활동 기록 필요 여부가 제품·운영 정책으로 정리된 뒤 UI와 백엔드 요구사항을 다시 작성한다. 그때 기존 `custom_modules/archive`를 보존한 상태에서 재사용 가능 범위와 변경 필요 범위를 평가한다. 결정 전에는 새 UI 디자인, 실제 NAS 데이터 이관, 권한 변경, 폴더 재설계, 버전·soft delete 구현, NAS 연동 제거를 진행하지 않는다.
