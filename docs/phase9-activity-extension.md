# Phase 9 확장 — KITEL 활동

## 변경 범위

기존 News 카테고리 `170`과 Main Menu 항목 `173`의 표시명을 `최근 진행 행사 보고`에서 `KITEL 활동`으로 바꾼다. 같은 News 게시판과 링크(`/index.php?mid=news&category=170`)를 유지한다. 다른 두 News 카테고리와 Seminar의 공통 게시판 목록은 그대로 사용한다.

활동 카테고리 목록은 왼쪽 정사각형 썸네일, 오른쪽 제목과 짧은 소개의 세로 목록이다. 검색·페이지네이션·관리자 쓰기·상세·댓글·첨부파일·기존 grant는 공통 게시판 로직을 재사용한다. 작성 폼에는 Rhymix 표준 문서 확장 필드 `activity_thumbnail`(`file`)과 `activity_teaser`(`text`)가 추가된다. 이 필드는 KITEL 활동 분류를 선택했을 때만 표시되며, 편집 중 썸네일을 별도로 업로드하거나 교체할 수 있다.

News는 제목/목록을 익명에게 공개하지만 본문 읽기는 허용된 회원에게만 가능하다. 따라서 `activity_teaser`는 관리자가 공개용으로 직접 입력한 경우에만 익명에게 보여준다. 비어 있으면 읽기 권한이 있는 회원에게만 본문 일부를 보여주고, 그 외에는 로그인 안내를 표시한다. 이미지 엔드포인트는 공개 활동 글의 선택된 썸네일 파일만 제공하고 파일의 문서·카테고리·공개 상태·MIME·저장 경로를 검사한다. 다른 첨부파일 다운로드 권한은 변경하지 않는다.

Home의 `home_dashboard`는 해당 카테고리의 최신 공개 글 최대 3건을 공지사항/과제현황과 작품전시회 사이에 배치한다. 공지사항 미리보기에서는 활동 카테고리를 제외해 한 글이 두 번 나오지 않게 한다. 데이터는 매 요청 News에서 읽으며 Home에 별도 사본을 저장하지 않는다.

## 로컬 개발환경 적용

1. `scripts/sync-dev.ps1`로 repository 코드를 Rhymix 실행본에 동기화한다.
2. `D:\rhymix_dev\php\php.exe scripts/configure-activity-dev.php`로 대상 식별과 작업 내용을 미리 확인한다. 기본값은 dry-run이다.
3. 같은 명령에 `--apply`를 붙여 개발 DB의 카테고리명·메뉴명·확장 필드 두 개를 갱신한다. 스크립트는 정확한 로컬 root, DB, News 모듈, 카테고리·메뉴 식별자를 검증하고 원본을 `D:\rhymix_dev\phase9-activity-backups`에 기록한다.
4. Rhymix 캐시를 재생성하고 `/index.php?mid=news&category=170`, Home, News 쓰기 화면을 확인한다. 다른 환경의 식별자는 먼저 별도 검토해야 한다.

이 문서는 기존 Figma handoff의 `최근 진행 행사 보고` 명칭보다 나중에 확정된 제품 요구사항을 기록한다. 운영 DB와 운영 메뉴를 이 스크립트로 변경하지 않는다.

## 로컬 검증

- News 카테고리·Main Menu·Footer가 모두 `KITEL 활동`으로 표시됐다. 다른 News 분류와 공통 게시판 화면은 기존 구조를 유지했다.
- 관리자 계정으로 별도 썸네일과 공개 소개를 포함한 임시 활동 글을 실제 작성·수정했다. 1440px·390px 목록에서 정사각형 이미지, 오른쪽 제목·소개, 검색·페이지네이션 영역, 가로 넘침 없음, 브라우저 오류 없음을 확인했다. Home에서는 공지사항/과제현황 다음, 작품 카드 전에 활동 카드가 보이고 공지사항과 중복되지 않았다.
- 익명 목록·Home의 공개 소개와 선택된 썸네일 이미지 응답은 정상이고, 익명 상세 본문은 기존 권한대로 403이었다. 공개 소개를 비우면 익명에게 본문이 노출되지 않으며 준회원에게는 실제 본문 일부가 목록·Home 모두에 표시됐다.
- 공개 소개에 HTML/JS payload를 입력했을 때 목록·Home 모두 텍스트로 표시되고 요소 생성이나 실행은 없었다. 작성 화면에서 활동 분류를 선택하면 확장 필드가 활성화되고 다른 분류를 선택하면 숨겨지며 제출에서 제외된다.
- 임시 게시글을 Rhymix 삭제 경로로 제거했다. 해당 문서·파일·확장 값이 DB에 남지 않았고 테스트 계정의 원래 비밀번호 해시를 복원했다. 로컬 메뉴·카테고리·확장 필드 설정과 적용 전 백업은 유지한다.
