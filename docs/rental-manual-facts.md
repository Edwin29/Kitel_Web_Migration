## 2. 최초 설치

**매뉴얼 독자(admin 클라이언트)는 설치를 하지 않는다.** 이미 설치·운영 중이다.
아래는 재설치·이전 시에만 필요한 절차이므로, 매뉴얼에서는 부록으로 빼거나 생략하는 것을 검토할 것.

🟢 `tools/install.php`, `README.md` §9

1. 소스를 `/volume1/kitel_web/xe/rental_dev/`에 배치
2. DB 테이블 생성 (CLI 전용, 안전장치로 `KITEL_RENTAL_INSTALL=1` 없으면 아무 것도 안 함)
   ```
   KITEL_RENTAL_MODE=production KITEL_RENTAL_INSTALL=1 /usr/local/bin/php74 tools/install.php --seed
   ```
   `--seed`는 권한 그룹(정회원=user, 관리그룹=admin)과 기본 카테고리 8종을 넣는다. 반복 실행해도 중복 생성 안 됨.
3. 서버에 `qrencode` 설치 (없으면 QR 화면 전부 실패 — §8 참고)
4. `/usr/local/bin/php74 tools/check.php`로 사전 점검

**전제 조건** 🟢
- XE가 같은 서버에 있고 `files/config/db.config.php`를 읽을 수 있어야 한다 (DB 접속 정보를 여기서 가져옴)
- Apache vhost에 `AllowOverride All` (`.htaccess` 접근 제어가 작동해야 함)

## 4. 주요 사용 흐름

### 4-1. 일반 사용자: 대여 🟢

```
홈 → [대여하기 QR 스캔]
  → 카메라로 기자재 QR 스캔 (연속 스캔 가능, 한 번에 하나씩 확인 팝업)
  → 담은 항목이 쌓임
  → [대여 목록으로]
  → 실제 사용자 이름/연락처/비고 입력 (선택)
  → [전체 대여 신청]
  → 내 대여 화면으로 이동
```

- 반납 예정일은 **대여일 +7일로 자동 설정**. 사용자는 고를 수 없다. 🟢 `rent_list.php`
- 대여 명의자는 로그인한 본인으로 고정(수정 불가), **실제 사용자**는 따로 적을 수 있다 🟢
  (준회원이 쓰고 정회원이 대신 빌리는 경우를 위한 칸)
- QR 대신 **기자재 상세 링크를 열기만 해도 자동으로 목록에 담긴다** 🟢 `item.php`
- 개수 관리 품목은 스캔 시 **수량 입력 팝업**이 뜬다 🟢 `scan.php`
- 묶음 QR을 스캔하면 **포함된 카테고리 선택 화면**이 뜬다 🟢

### 4-2. 일반 사용자: 반납 🟢

```
홈 → [반납하기 QR 스캔] → 스캔 → [반납 목록으로] → [반납 확정]
```
- 반납은 **누가 빌렸는지 따지지 않는다** — 다른 사람이 빌린 것도 반납 처리 가능 🟢
  (`return_list.php`, 코드 주석에 의도 명시)
- 단, `my.php`에서 직접 반납하는 경로는 본인 또는 관리자만 🟢 `return.php`

### 4-3. 관리자: 기자재 등록 (3가지 경로) 🟢

| 경로 | 언제 | 화면 |
|---|---|---|
| 단건/소량 | 몇 개 추가 | `item_new.php` 기본 탭 — 카테고리·수량·위치·특이사항 |
| 엑셀 파일 | 물품현황표 통째로 | `item_new.php?tab=csv` — `.xlsx` 드래그앤드롭 |
| CSV 붙여넣기 | 시트에서 복사 | 같은 화면 텍스트 영역 |

**엑셀/CSV는 반드시 미리보기를 거친다** 🟢 — 무엇이 추가/수정/폐기되는지 보여준 뒤 한 번 더 눌러야 반영.

**수량 해석 모드 2가지** 🟢 (핵심. 매뉴얼에서 가장 강조할 부분)

| 모드 | 의미 | 쓸 때 |
|---|---|---|
| 추가 | 적힌 수량만큼 **새로 만듦** | 신규 입고 |
| 맞추기 | 적힌 수량을 **목표 총 개수**로 봄 | 현황표를 갱신해 다시 넣을 때 |

> 같은 시트를 "추가"로 두 번 넣으면 개수가 두 배가 된다. 🟢

### 4-4. 관리자: 내보내기 → 편집 → 가져오기 왕복 🟢

```
기자재 관리 → [CSV 내보내기]  (현재 걸린 필터가 그대로 반영됨)
  → 시트에서 위치/특이사항 수정
  → 가져오기 → 미리보기 → 적용
```
- `item_id`가 있는 행 = **수정**(위치·특이사항만), 빈 행 = **신규 추가** 🟢
- 카테고리·상태는 CSV로 바뀌지 않고 "무시됨"으로 표시 🟢
- 운영 데이터 542행으로 왕복 검증: **변경 0건** 🟢 (무손실 확인)

### 4-5. 관리자: 연체 처리 🟢

```
대시보드 연체 지표/목록 → 대여 현황(연체 필터)
  → 강제 반납: 사유 필수 + 반납 후 상태 선택(대여 가능/고장/대여 불가/분실)
  → 묶음은 개수 지정해 일부만 반납 가능
```

### 4-6. 관리자: QR 라벨 발행 🟢

```
기자재 관리 → 체크박스로 선택 → [선택 항목 QR 인쇄] → A4 라벨 그리드 → 브라우저 인쇄
```
- **한 번에 최대 200장.** 초과 시 안내하고 앞 200장만 출력 🟢
- 선택 없이 누르면 차단됨 🟢
- QR이 가리키는 주소는 `canonical_base_url` 기준 절대 URL 🟢

🔴 **라벨 용지 규격·프린터·부착 방법은 코드에 없음** — 현장 관행 확인 필요

## 5. 설정 가능한 옵션

환경변수 우선, 없으면 `app/config.php` 기본값. 🟢
**현재 운영 서버는 환경변수를 쓰지 않으므로 전부 `config.php` 기본값이 적용된다** 🟢 (실측)

| 설정 | 현재 운영값 🟢 | 의미 |
|---|---|---|
| `mode` | `production` | `local`이면 파일 기반 테스트 DB + 가짜 로그인 |
| `default_due_days` | **7** | 대여 기간(일) |
| `require_qr_on_return` | **off** | on이면 내 대여 목록에서 바로 반납 불가, 기자재 QR 화면에서만 |
| `require_trusted_network_for_rental` | **on** | 대여·반납을 특정 네트워크에서만 허용 |
| `trusted_network_cidrs` | **`192.168.1.0/24`** | 허용 대역 (콤마로 여러 개) |
| `trusted_proxies` | **(없음)** | 비어 있으면 `X-Forwarded-For` 무시하고 `REMOTE_ADDR`만 사용 |
| `base_url` | `/rental_dev/public` | 앱 내부 링크 접두 |
| `canonical_base_url` | `https://kitel.kw.ac.kr/rental_dev/public` | QR에 새겨지는 절대 URL |
| `qr_backend` / `qrencode_path` | `qrencode` | QR 생성기 (**사용 가능 확인됨** 🟢) |

### 화면에서 바꿀 수 있는 것 (admin) 🟢
- 권한 그룹 매핑 (`admin/permissions.php`)
- 카테고리별 **개별/개수 관리 전환**, **1인당 대여 제한**
- 카테고리·묶음 구조
- 기자재 위치/특이사항/관리자 메모

**현재 1인당 제한이 걸린 카테고리 14개** 🟢: 니퍼 1개 / 그 외 13종(가위·점프선·각종 케이블·프로브·납 등) 3개

| QR 스캔 | 카메라 화면에 초록 사각형이 QR을 감싸고, 확인 팝업이 뜬 뒤 담긴 개수가 늘어남 |
| 대여 신청 | "N개 대여 신청이 완료되었습니다" → 내 대여 화면에 표시 |
| 반납 | "N개 반납이 완료되었습니다" → 내 대여에서 사라짐 |
| 상태 변경/폐기 | 사유를 넣어야 버튼이 동작하고, 처리 로그에 즉시 남음 |
| 목록 정렬 | 대여 현황·처리 로그는 **최신이 맨 위** |
| 가져오기 | 미리보기 화면이 먼저 뜨고, 적용 후 "N개 추가 · N건 수정 · N개 폐기 완료" |
| CSV 내보내기 | 화면에 걸어둔 필터가 그대로 반영된 파일이 받아짐 |
| QR 인쇄 | 라벨마다 라벨명·QR·`EQ-XXXXXXXX` 코드가 함께 보임 |
| 네트워크 점검 | 동방에서 열면 "신뢰 네트워크로 인식됨 — 대여/반납 가능" |

**기자재 상태 값 7종** 🟢 `app/helpers.php` `status_label()`
`대여 가능(available)` `대여 중(borrowed)` `대여 불가(unavailable)` `고장(broken)` `분실(lost)` `폐기/사용 종료(retired)`
대여 상태: `반납 완료(returned)` `강제 반납(force_returned)` `취소(cancelled)`

> 현재 운영 데이터는 **정상 542개 전부 `available`, 폐기 20개**, 대여 중 0건 🟢

## 7. 흔한 오류와 해결법

전부 코드에서 실제로 발생 가능한 것만. 🟢 메시지는 원문 그대로.

### 7-1. 사용자가 자주 만날 것

| 증상 / 메시지 | 원인 | 해결 |
|---|---|---|
| **"동방 와이파이에 연결된 상태에서만 대여/반납할 수 있습니다."** | IP 제한(`require_trusted_network`)에 걸림 | 동방 와이파이로 전환. 계속 뜨면 관리자에게 → **설정 > 네트워크 점검** |
| **"카메라 스캔은 모바일에서만 이용할 수 있어요."** | User-Agent가 PC로 판정됨 | 휴대폰으로 접속. PC에서는 목록 확인만 |
| 카메라가 안 켜짐 | 브라우저 카메라 권한 거부 | 브라우저 설정에서 권한 허용 |
| **"등록되지 않은 QR입니다."** | 라벨이 이 시스템 것이 아니거나 폐기된 기자재 | 관리자에게 확인 |
| **"…: 지금은 대여할 수 없습니다 (고장)."** | 해당 상태에서는 대여 불가 | 다른 물품 선택 |
| **"…: 지금 대여 중이 아닙니다."** | 반납 모드인데 대여 중이 아님 | 대여 모드인지 확인 |
| **"이 물품은 1인당 최대 N개까지 대여할 수 있습니다. 현재 M개 대여 중입니다."** | 카테고리 1인당 제한 | 먼저 반납하거나 관리자에게 요청 |
| **"재고 부족"** | 가용 수량보다 많이 요청 | 수량 줄이기 |
| **"세션이 만료되었습니다. 새로고침 후 다시 시도해 주세요."** | CSRF 토큰 만료(장시간 방치) | 새로고침 후 재시도 |
| **"이미 대여 중이거나 대여할 수 없는 기자재입니다."** | 담아둔 사이 다른 사람이 먼저 빌림 | 목록 갱신 후 재시도 |

### 7-2. 관리자가 만날 것

| 증상 / 메시지 | 원인 | 해결 |
|---|---|---|
| **"상태 변경 사유를 입력해 주세요." / "폐기 처리 사유를 입력해 주세요."** | 사유는 필수 | 사유 입력 |
| **"대여 중인 기자재는 직접 상태를 바꿀 수 없습니다. 먼저 반납 처리해 주세요."** | 대여 중 보호 | 강제 반납 후 상태 변경 |
| **"대여 중인 기자재가 있는 카테고리는 삭제할 수 없습니다."** | 삭제 보호 | 전부 반납 후 재시도 |
| **"이미 있는 카테고리와 이름이 겹칩니다."** | 카테고리명 중복(또는 특수문자 제거 후 같아짐) | 이름 변경. **가져오기 전체가 취소되므로 데이터는 안전** |
| **"가져오기를 취소했습니다 (아무것도 반영되지 않았습니다)"** | 가져오기 도중 오류 → 전량 롤백 | 메시지의 원인 수정 후 재시도 |
| **"N행: 카테고리명이 비어 있습니다." / "수량이 1 이상이어야 합니다."** | CSV 행 오류 | 그 행만 건너뛰고 나머지는 진행됨 |
| **"item_id N 인 기자재를 찾을 수 없습니다."** | 왕복 CSV에서 `item_id`를 잘못 건드림 | 다시 내보내서 시작 |
| **"QR은 한 번에 200장까지 인쇄할 수 있습니다."** | 선택 과다 | 나눠서 인쇄 |
| **QR 화면이 흰 화면/500 오류** | 서버에 `qrencode`가 없거나 실행 불가 | 서버에 `qrencode` 설치. 🟢 현재는 **정상 설치됨** |
| **"관리자 권한이 없습니다." (403)** | 권한 그룹 미설정 | 설정 > 권한 그룹에서 XE group_srl 추가 |
| **"기자재를 찾을 수 없습니다." (404)** | 삭제/폐기된 대상 링크 | 목록에서 다시 진입 |

### 7-3. 서버 수준 (관리자가 알아둘 것)

| 메시지 | 의미 |
|---|---|
| `XE DB 설정 파일을 찾을 수 없습니다.` | XE 경로(`xe_root`)가 틀렸거나 XE가 이동됨 |
| `KITEL rental app path is not configured.` | `app/` 폴더를 못 찾음 (배포 누락) |
| `KITEL_RENTAL_MODE is local on a non-local host.` | 테스트 모드가 운영 서버에 올라감 — 즉시 조치 |
| `Invalid CSRF token` (419) / `Method Not Allowed` (405) | 정상적인 보호 동작 |

## 8. 사용자가 해서는 안 되는 조작

🟢 전부 코드 근거 있음.

### 8-1. 관리자 — 데이터가 상하는 것

1. **CSV `item_id` 열을 지우거나 바꾸지 말 것.** 기자재를 식별하는 유일한 기준. 지우면 전부 신규 추가로 처리된다.
2. **"맞추기" 모드에서 폐기 체크박스를 습관적으로 켜지 말 것.** 시트에 없는 기자재가 전부 폐기 대상이 된다. 미리보기에서 폐기 목록을 반드시 눈으로 확인.
3. **같은 시트를 "추가" 모드로 반복 가져오지 말 것.** 개수가 배로 늘어난다.
4. **카테고리 삭제를 가볍게 쓰지 말 것.** 기자재가 있으면 그 기자재가 **전부 폐기 처리**되고 카테고리는 비활성화된다.
5. **카테고리명 변경 시 기존 기자재 라벨이 전부 새 이름으로 바뀐다.** 이미 인쇄해 붙인 라벨과 화면 표시가 어긋난다. (QR 자체는 계속 동작 — 코드가 아니라 라벨명만 달라짐)
6. **폐기는 되돌리는 화면이 없다.** 🟢 `retire_item()`은 있으나 복구 UI 없음.

### 8-2. 관리자 — 하면 안 되지만 막혀 있는 것 (안심해도 되는 것)

- 대여 중인 기자재 상태 변경/폐기 → 차단됨
- 대여 중인 기자재가 있는 카테고리 삭제 → 차단됨
- 사유 없이 상태 변경/폐기/강제 반납 → 차단됨
- 다음 라벨 번호를 현재보다 작게 → 차단됨

### 8-3. 일반 사용자

1. **다른 사람 명의로 대여하지 말 것.** 대여 명의자는 로그인 계정으로 고정되며, 대신 쓰는 사람은 "실제 사용자" 칸에 적어야 한다.
2. **QR 라벨을 떼거나 바꿔 붙이지 말 것.** `public_code`가 물품 식별자다.
3. **기자재 상세 링크를 브라우저 즐겨찾기로 반복 열지 말 것** — 여는 것만으로 목록에 담긴다.

### 8-4. 서버 관리자

1. **`app/`, `database/` 폴더를 웹에서 열리게 만들지 말 것.** `.htaccess`가 막고 있다.
2. **`public/`에 임시 파일(`debug_*.php` 등)을 두지 말 것.** 화이트리스트 방식이라 자동 차단되지만, `.htaccess`에 추가하는 실수를 하지 말 것.
3. **`KITEL_RENTAL_MODE`를 `local`로 두지 말 것.**

## 9. 🔴 코드에서 확인할 수 없는 것 — 사람에게 확인 필요

매뉴얼에 넣으려면 답이 필요한 항목. **추측하지 않았다.**

### 9-1. 운영 정책
1. **대여 기간 7일이 실제 규칙인가?** 코드 기본값일 뿐, 동아리 규정인지 불명.
2. **연체 시 어떻게 하는가?** 코드는 "연체"로 표시만 한다. 제재·독촉·연장 절차 없음. 연장 기능 자체가 없다 🟢.
3. **분실·파손 시 변상 규정.** 코드에 없음.
4. **누가 관리자인가.** `관리그룹`(3명)·`기술부`(6명)로 매핑돼 있으나, 실제 담당자·역할 분담은 불명.
5. **`staff`(보조 권한) 등급을 쓸 계획인가?** 코드에 선택지만 있고 판정에 미사용 🟢.

### 9-2. 물리적 운영
6. **QR 라벨 용지 규격, 프린터, 부착 위치·방법.**
7. **동방 물품현황표(엑셀)의 정확한 양식과 관리 주체.** 코드는 "물품명/현재 수량/비고" 블록 반복을 인식하지만 🟢, 실제 파일 위치·갱신 주기는 불명.
8. **기자재 실물 위치 표기 체계** (`location` 칸에 무엇을 적는 규칙인지).

### 9-3. 환경
9. **동방 와이파이 대역이 `192.168.1.0/24`가 맞는가.**
   🟡 **정황 증거 있음**: 사용자 경로 대여가 **43건 성공**했고, 이 경로는 IP 제한 통과가 필수다 🟢.
   즉 최소한 일부 기기·시점에는 맞았다. 다만 **모든 기기·SSID를 덮는지는 미확인** — 관리자 화면
   **설정 > 네트워크 점검**으로 동방/외부 각각 확인 필요.
10. **휴대폰 카메라 스캔의 브라우저 요건.** HTTPS·카메라 권한이 필요한 것은 브라우저 정책이며 코드 밖 사실.
    실제로 어떤 기종/브라우저에서 문제가 있었는지는 사용 경험 필요.
11. **동시 사용자 수·피크 시간대.** 서버가 저사양(DS218)이라 매뉴얼에 안내가 필요할 수 있으나 실측 데이터 없음.

### 9-4. 문서화 범위 결정 필요
12. **설치 절차를 매뉴얼에 넣을 것인가.** 클라이언트는 admin 사용자이지 서버 관리자가 아닐 수 있다.
13. **`/rental`(최종 경로) 전환 계획을 언급할 것인가.** 현재는 `/rental_dev/public/`에서 운영 중 🟢.
14. **XE 인증 어댑터 교체(Rhymix 이전) 이후 화면이 바뀌는가.** 로드맵 8번 미착수 상태.

## 10. 매뉴얼 작성 시 유의점 (조사자 메모)

- **가장 강조해야 할 것**: 가져오기의 **추가 vs 맞추기** 모드. 이걸 잘못 쓰면 재고가 두 배가 되고,
  되돌리려면 일일이 폐기해야 한다. 미리보기를 반드시 보게 하는 문구가 필요.
- **두 번째**: 카테고리 삭제·폐기가 되돌릴 수 없다는 점.
- **화면 이름은 코드의 실제 표기를 그대로 쓸 것** (사이드바: 개요/기자재/대여/기록/설정).
- **용어 통일 필요**: 코드가 "개별 관리(unique) / 개수 관리(bulk)"를 쓴다. 매뉴얼도 이 용어로 가는 것이 안전.
- 라벨 번호는 폐기 후 **재사용된다**(니퍼-2를 폐기하고 새로 만들면 다시 니퍼-2). 의도된 동작이나
  이력을 볼 때 혼동할 수 있으므로 한 줄 언급 권장 🟢.
