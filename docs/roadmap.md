## 2. NAS 실사에서 새로 확인된 사실 (2026-09-07, Tailscale SSH)

기존 문서들이 가정하거나 추정만 하고 있던 부분을 실제 운영 NAS에 접속해 직접 확인함. 아래는 기존 문서 내용을 정정하거나 보강하는 내용.

### 2-1. 운영 서버 스펙 정정
- **PHP는 7.4가 아니라 8.1.9**임을 실측으로 확인(`php -v`). 기존 문서([xeadmin-site-analysis.md](xeadmin-site-analysis.md), [remaining-work.md](remaining-work.md))에 적힌 "운영 서버 PHP 7.4" 추정은 **틀렸음** — DSM Web Station 설정만 보고 실제 CLI 버전은 확인 안 했던 게 원인으로 보임. 로컬 dev(PHP 8.2.33)와 큰 차이 없어 **배포 시 PHP 버전 문제는 사실상 해소됨**.
- MariaDB 10.11.11 (Synology MariaDB10 패키지, `/var/packages/MariaDB10/`), DSM 7.2.2, 기종 Synology DS218(aarch64, 저전력 NAS).
- 디스크: volume1 890G(214G 여유), volume2 2.7T(1.2T 여유) — 신규 사이트+레거시 아카이브+NAS Drive 자료 전부 동시 보관해도 공간은 충분함.
- 웹서버: nginx + Apache(php-fpm), 실제로 지금도 활발히 트래픽 처리 중(php-fpm 워커 다수 가동).

### 2-2. 운영 DB가 백업 시점보다 더 진행되어 있음
`backup_20260417.sql` 기준으로 설계했던 [data-migration-plan.md](data-migration-plan.md)의 수치가 지금 라이브 DB와 다음처럼 벌어져 있음:

| | 백업(4월) | 현재 라이브 | 차이 |
|---|---|---|---|
| xe_documents | 6,400 | 6,544 | +144 |
| xe_comments | 14,558 | 14,751 | +193 |
| xe_member | 703 | 702 | -1 |

특히 **과제게시판(module_srl 56725)이 1,094→1,180건(+86), 품평회게시판(38744)이 645→703건(+58)**으로 늘어 — 두 게시판 다 지금도 활발히 쓰이고 있다는 뜻. **실제 마이그레이션 실행 직전에는 반드시 새 백업을 떠야 함**(4월 백업으로 하면 최근 몇 달 활동이 통째로 누락됨).

### 2-3. 기자재 대여 시스템(rental_dev) — 이미 알던 것보다 더 진행돼 있고, 관련 조사 흔적도 발견
- `rental_dev` 소스가 [xeadmin-site-analysis.md](xeadmin-site-analysis.md) 작성 시점 이후로 더 개발된 상태: **묶음(bundle) QR, 카테고리 QR, CSV import/export 관리자 화면**(`bundle_qr.php`, `category_qr.php`, `run_bundle_migration.php` 등)이 새로 생겼고, DB 마이그레이션 파일도 2026-07/08 날짜로 추가됨. 즉 rental_dev는 이 워크스페이스가 아는 것보다 더 앞서 있음.
- `/rental`(운영 배포 경로)에 **`check_xe_groups_k2026.php`, `check_db_k2026.php`, `check_xe_login_k2026.php`, `check_cookies_k2026.php`** 라는 진단 스크립트들이 있는데, 내용을 보니 정확히 이번 로드맵 8번(대여 시스템 인증 어댑터 교체)과 같은 걸 조사하던 스크립트임(XE 세션/로그인 정보를 읽어보는 테스트 코드). **누군가 이미 이 작업을 부분적으로 건드려본 흔적**임.
- `.agents`라는 빈 폴더가 `xe/`와 `rental_dev/` 양쪽에 있음 — AI 코딩 도구를 쓴 흔적으로 보이는데 실제 커밋 이력은 없음(`.git` 폴더도 있지만 비어있어 실제 버전관리는 안 되고 있음).

**→ 확인 필요**: 이 조사/개발을 누가 했는지, 진행 상황이 어디까지인지 파악 후 이번 마이그레이션 작업과 중복되지 않게 조율 필요.

### 2-4. 자료실行 "NAS Drive 이관" 대상 실측 — 예상보다 훨씬 큼
지금까지 문서에는 "NAS Drive 전체 이관 예정"이라고만 적혀 있었고 실물 규모는 확인한 적이 없었음. 실제로 재보니:

| NAS 공유폴더 | 용량 | 내용 |
|---|---|---|
| `document` | 113G | 총회 자료, 품평회 제안서(43기/48기), 세미나, 족보 및 자료 등 |
| `임원단` | 80G | 2019~2026년 임원진 문서(회의록 등), **개인 학번 기반 계정 폴더 다수 포함** |
| `photo` | 99G | 2005~2026년 공식 행사 사진(Synology Photos 연동) |
| `대회 공모전` | 11G | 2006~2012년 각종 공모전 참가 자료 |
| `교육 자료` | 8.4G | 데이터시트, 강의자료, "작품&세미나&학술제관련자료실" 등 |
| `KITEL 관련 자료` | (소량) | 2007~2011년 작품전시회/축제 아카이브, 축제자료실(2025년까지 갱신) |

**합계 약 311GB** — xe 첨부파일(11G)의 30배 규모. 이전에 이 규모를 몰랐던 채로 "자료실에 전부 이관"이라고 방침만 정해뒀던 것 → **범위 재검토가 필요함**: 이 전부를 새 Rhymix 자료실 모듈에 넣을지(폴더/파일 UI로), 아니면 임원단·photo처럼 성격이 다른 것들은 계속 별도 NAS Drive/Synology Photos로 두고 자료실에는 교육자료·document 위주로만 옮길지 결정 필요. `임원단` 폴더는 개인 학번이 노출된 계정으로 소유돼 있어 다루는 사람 확인 및 개인정보 취급 주의가 필요함.

## 4. 리스크/조율 필요 사항

1. **rental_dev 중복 작업 위험** (2-3번) — 누가 어디까지 손댔는지 확인 전에 인증 어댑터 작업에 착수하면 충돌 가능성 있음
2. **자료실 NAS Drive 이관 범위 재정의 필요** (2-4번) — 311GB 전체 이관은 비현실적일 수 있어 우선순위/대상 재선별 필요, 개인정보(임원단 폴더) 취급 방식도 함께 결정
3. **데이터 마이그레이션 실행 시점의 백업 최신화** (2-2번) — 활발히 쓰이는 게시판이 있어 임박한 시점에 재백업 필수
4. **세미나/공유게시판이 골격만 있음** — 디자인 통합 전에 최소한 세미나 게시판의 확장변수(발표자/발표일)는 구현해두는 게 나중에 재작업을 줄임

## 5. 다음 우선순위 제안 (진행도 기준)

1. rental_dev 현황 확인 (조율 필요 사항 1번) — 다른 작업과 병행 가능, 사람에게 물어보는 것부터
2. 세미나 게시판 확장변수 구현 (골격만 있는 것 중 가장 작음)
3. 데이터 마이그레이션 스크립트 실제 구현 착수 (설계 이미 완료)
4. 자료실 NAS Drive 이관 범위 재논의 후 착수
5. 디자이너 목업 완성 대기, 완성되는 대로 퍼블리싱 반영 병행
6. 배포 전환 절차 설계는 위 항목들이 어느 정도 마무리된 뒤
